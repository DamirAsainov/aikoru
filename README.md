# AIKORU — офлайн-ассистент пространственной ориентации (прототип v0.1)

Голосовой помощник для людей с нарушениями зрения. Он смотрит через USB-камеру,
предупреждает об опасностях и изменениях вокруг, узнаёт знакомых людей по лицу,
а по голосовой команде описывает обстановку или ищет предмет.
Поддерживает русский и казахский языки. После установки работает полностью офлайн.

## Как это работает

```
 микрофон ──► Vosk ru+kk ──► «Айкору» ──► Silero VAD (запись команды) ──► Vosk ru+kk ──► разбор команды
                                                                                            │
 камера ──► YOLOE + ByteTrack (~3 кадра/с) ──► события ──► YuNet+SFace (лица) ─────────┐   │
        └─► YOLOE (по запросу: «найди дверь») ◄── словарь / NLLB ru,kk→en ◄────────────┼───┤
        └─► LFM2.5-VL («что вокруг?») ──► NLLB en→ru,kk ───────────────────────────────┤   │
                                                                                       ▼
                                                       Silero TTS v5 CIS (голос zhadyra, ru + kk) ──► наушники
```

| Компонент | Модель | Зачем |
|---|---|---|
| Детекция | YOLOE-11s (ultralytics, без ветки масок) | Поиск объектов по тексту или по образцу (open-vocabulary) |
| Трекинг | ByteTrack (ultralytics) | Отличает новый объект от уже известного |
| Лица | OpenCV YuNet + SFace | Узнаёт знакомых, локальная база `data/faces.json` |
| VLM | LFM2.5-VL-450M (Liquid AI) | Описание сцены и ответы на вопросы о кадре |
| Перевод | NLLB-200 600M, CTranslate2 int8 | VLM и YOLOE понимают только английский |
| STT | Vosk small ru + small kz | Слово активации и команды. Silero STT не поддерживает казахский |
| VAD | Silero VAD | Определяет конец команды по паузе |
| TTS | Silero v5_cis_base_nostress | Один голос для ru (`ru_zhadyra`) и kk (`kaz_zhadyra`) |
| Ударения | silero-stress | Расставляет ударения для русского TTS |

## Установка

Нужны Python 3.11–3.13 и Windows, Linux или macOS. Видеокарта не обязательна:
при `device: auto` используется CUDA, если она есть, иначе CPU.

```bash
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate

# PyTorch: с NVIDIA GPU
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128
# ...или без GPU (~110 МБ вместо ~3 ГБ)
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu

pip install -r requirements.txt
python scripts/download_models.py  # один раз, ~2.5 ГБ; после этого интернет не нужен
```

### Слабый ноутбук (8 ГБ RAM, GeForce MX350/MX250 2 ГБ, Intel i5)

Колёса PyTorch для CUDA 12.8 не поддерживают видеокарты Pascal (MX150/MX250/MX350, GTX 10xx).
Для них ставьте сборку для CUDA 12.6:

```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu126
```

Если сборка torch не поддерживает GPU, AIKORU сам переключается на CPU и пишет об этом в лог.

На CPU фоновый трекер работает через OpenVINO (пакет `openvino` из requirements.txt). При первом
запуске YOLOE экспортируется с зашитыми классами `standard_classes` во вход 512×384 (~10 с, папка
`models/yoloe-11s-<хэш>-384x512_openvino_model`); при смене классов или `imgsz` экспорт повторяется.
На i5-10400 прогон трекера занимает ~50 мс вместо ~86 мс у PyTorch. Для этого приложение само ставит
`OMP_WAIT_POLICY=PASSIVE`: без неё потоки torch отнимают ядра у OpenVINO (~150 мс на прогон),
а с ней перевод NLLB на ~0.13 с медленнее, поэтому при видеокарте NVIDIA PASSIVE не включается
и трекер остаётся на PyTorch/CUDA. Выбор задаёт `detector.backend: auto | torch | openvino`.

**INT8-трекер** (`detector.int8: true`, по умолчанию): OpenVINO-модель квантуется NNCF на своих кадрах
с камеры и работает в 4–5 раз быстрее FP32 (на тестовой машине ~25 мс против ~85–130 мс), полнота
на coco128 та же (люди 149 против 146 из 254). Кадры снимаются один раз:

```bash
python scripts/capture_calib.py   # 300 кадров за ~2.5 мин в data/calib; носите камеру как обычно
```

При следующем запуске модель экспортируется в INT8 (~30 с, папка `…-int8_openvino_model`). Пока кадров
меньше 50, трекер остаётся в FP32 (в логе предупреждение). Чтобы откалибровать заново, удалите эту папку.

**VLM через llama.cpp** (`vlm.backend: auto`): если VLM идёт на CPU и скачаны `llama-server` и GGUF
(`scripts/download_models.py`), та же LFM2.5-VL-450M работает в Q8_0 отдельным процессом на 127.0.0.1.
На тестовой машине: ~1 с на описание вместо ~2.1–2.5 с, ~0.5 ГБ вместо ~1.3–2 ГБ, загрузка ~2 с вместо
~30–90 с. Кадр уменьшается до 384 px: крупнее llama.cpp режет его на тайлы (7 тайлов — ~25 с).

Как распределяется нагрузка при настройках по умолчанию:

| Компонент | Где | Память | Время |
|---|---|---|---|
| YOLOE + трекинг (`imgsz: 512`) | GPU (2 ГБ хватает) или CPU | ~0.3 ГБ | GPU: ~20 мс/кадр, CPU (OpenVINO INT8): ~25 мс/кадр |
| LFM2.5-VL-450M (`image_tokens: 64`) | CPU: llama.cpp Q8_0 (GPU только при ≥4 ГБ VRAM) | ~0.5 ГБ | ~1 с на ответ |
| NLLB-200 int8 | CPU | ~0.6 ГБ | 0.1–0.4 с на фразу |
| Vosk, Silero TTS/VAD, лица | CPU | ~0.5 ГБ | — |

Всё приложение на чистом CPU занимает ~4.4 ГБ RAM (замер на тестовой машине, 4 потока).
Если памяти не хватает:
- `vlm.path: smolvlm-256m`, `vlm.repo: HuggingFaceTB/SmolVLM-256M-Instruct`: ~1 ГБ вместо 1.8 ГБ и ~1 с на ответ, но описания беднее и чаще ошибочны;
- `detector.imgsz: 416`: быстрее, но теряет людей на крупном плане;
- `detector.watch_interval_s: 1.5`: реже фоновый трекинг, когда в кадре что-то слегка шевелится.

FP16 на GTX 10xx/MX-сериях работает в десятки раз медленнее FP32, поэтому на них везде используется FP32.

## Запуск

```bash
python -m aikoru                 # голосовой режим
python -m aikoru --show          # + окно с видео и рамками (Esc — выход)
python -m aikoru --text          # команды с клавиатуры (отладка без микрофона)
python scripts/selftest.py       # самопроверка всех компонентов
```

Загрузка моделей занимает 1–3 минуты. Когда всё готово, система говорит «Система готова».

## Веб-интерфейс

Пока AIKORU работает, откройте **http://127.0.0.1:8765**. В интерфейсе:

- видео с камеры, поверх него рамки треков: знакомые подписаны именем, опасности выделены красным;
- «Эфир»: всё, что система произносит, и все команды, в том числе голосовые;
- ввод команд на RU/KK и кнопки быстрых команд;
- база знакомых: удалить человека или запомнить того, кто сейчас в кадре.

Тема по умолчанию светлая или тёмная, как в системе. Принудительно: `?theme=light` или `?theme=dark`.
Отключить интерфейс: `--no-web`. Порт и адрес задаются в разделе `web` в `config.yaml`.
С `host: 0.0.0.0` интерфейс откроется с телефона в той же сети. Учтите: тогда видео
с камеры будет видно всем в этой сети.

## Голосовые команды

Сначала скажите слово активации **«Айкору»**, дождитесь короткого сигнала и произнесите команду.
Язык ответа совпадает с языком команды.

| Действие | Русский | Қазақша |
|---|---|---|
| Описать обстановку | «что вокруг», «что впереди», «опиши» | «айналада не бар», «сипатта» |
| Найти предмет | «найди дверь», «где светофор» | «есікті тап», «бағдаршам қайда» |
| Вопрос о кадре | «что написано на вывеске?» | любая фраза из 2+ слов |
| Кто рядом | «кто это», «кто рядом» | «бұл кім», «кім бар» |
| Запомнить человека | «запомни как Айгерим» | «Айгерім деп есте сақта» |
| Забыть человека | «забудь Айгерим», «забудь всех» | «Айгерімді ұмыт», «барлығын ұмыт» |
| Запомнить свой предмет | «запомни мои ключи», «запомни предмет зонт» | «менің кілтімді есте сақта» |
| Найти свой предмет | «где мои ключи», «найди мою кружку» | «кілтім қайда» |
| Забыть предмет | «забудь ключи», «забудь все вещи» | «кілтті ұмыт» |
| Что в памяти | «что ты помнишь» | «не есіңде» |
| Пауза фоновых подсказок | «стоп», «тише» | «тоқта» |
| Включить подсказки | «продолжай» | «жалғастыр» |

Если предмета нет в словаре (`aikoru/lexicon.py`), его название переводится на английский
через NLLB, поэтому искать можно что угодно, например «найди красный зонт».

**Запоминание человека.** Человек смотрит в камеру, вы говорите «Айкору, запомни как Айгерим».
Система берёт три кадра и сохраняет лицо под этим именем. Имя распознаёт Vosk, и редкие имена
маленькая модель может услышать неверно. Тогда повторите команду или поправьте имя в `data/faces.json`.

**Запоминание предмета.** Поднесите предмет к камере и скажите «Айкору, запомни мои ключи».
YOLOE находит предмет по названию (ближайшую к центру рамку на трёх кадрах), а затем
кодирует его как **визуальный промпт** (SAVPE) в 512-мерный эмбеддинг. Он сохраняется
в `data/objects.json`. По команде «где мои ключи» детектор ищет по этому образцу вместо
текста: именно ваши ключи, а не любые. Поиск занимает один обычный проход YOLOE (~40 мс на GPU)
без текстового энкодера. Если предмет по названию не найден, запоминается центральная
область кадра, и система об этом скажет. Повторное «запомни» с тем же названием дополняет образец
(например, с другого ракурса).

Кого запоминать, человека или предмет, система решает так: притяжательное слово («мои», «менің»),
слово «предмет»/«вещь»/«зат» или известный предмет («ключи», «кружку») означают предмет,
«человека»/«лицо»/«адам» означают человека. Иначе запоминается лицо, если оно есть в кадре, а если нет, то предмет.

## Фоновый режим: только изменения

YOLOE с трекером ByteTrack работает с адаптивной частотой. Перед ним в потоке камеры стоит дешёвый
детектор движения MOG2 (кадр 160 px, ~1 мс, секция `motion`). Режимов три:

| Режим | Когда | Частота |
|---|---|---|
| active | Новый/ушедший/приближающийся объект или движется весь кадр (человек идёт, поворачивает голову) | ~3 кадра/с (`detector.scan_interval_s`) |
| watch | Что-то шевелится в части кадра | 1 кадр/с (`detector.watch_interval_s`) |
| idle | Движения нет 3 с (`detector.active_hold_s`) | раз в 5 с (`detector.idle_interval_s`) |

В режиме idle любое движение будит трекинг сразу, не дожидаясь 5 секунд. Раз в 30 секунд в лог
пишется сводка: число прогонов по режимам, время прогона и загрузка CPU.
С `motion.enabled: false` остаются только active и watch, а объект ближе ~4 м тоже считается изменением.
У каждого объекта есть свой номер трека, поэтому система говорит только о **новом**:

| Событие | Пример фразы | Когда |
|---|---|---|
| Опасность | «Осторожно! Машина прямо, около трёх метров.» | Транспорт, столб или лестница прямо по курсу ближе 4 м. Повторяется, только если объект подошёл вплотную. Прерывает другие подсказки |
| Знакомый пришёл | «Справа: Айгерим, около двух метров.» | Лицо узнано в базе |
| Незнакомец | «Прямо: незнакомый человек, около двух метров.» | Лицо не узнано за 2 с, человек ближе 4 м. Несколько человек сразу объявляются одной фразой |
| Знакомый ушёл | «Айгерим больше не видно.» | Пропал и не вернулся за 4 с |
| Новый объект | «Слева: скамейка, около трёх метров.» | Новый трек ближе 4 м. Дальние объекты объявляются, когда подойдут ближе |

Пока ничего не меняется, система молчит. Если трекер дал тому же объекту новый номер
(после перекрытия или моргания детекции), новый трек наследует состояние старого:
того же класса, рядом и похожего размера. Повторного объявления не будет.

**Приватность.** `data/faces.json` хранит биометрические эмбеддинги лиц. Файл остаётся
на устройстве и исключён из git. Запоминайте людей только с их согласия.

## Настройка

Все параметры находятся в `config.yaml`: камера, интервал сканирования, список объектов,
порог слова активации, голос и т.д.

## Ограничения прототипа

- **Расстояние** считается грубо, по одной камере: по известной высоте объекта и высоте рамки. Для объектов без известной высоты используется размер рамки. Точность ±30–50%.
- **Слово активации** ловится нечётким сравнением с распознанным текстом. Если срабатывает плохо, добавьте свои варианты в `voice.wake_words` или измените `wake_threshold`.
- **Лица** узнаются на расстоянии примерно до 3–4 м: лицо должно быть не меньше 40 px. В темноте и при повороте в профиль распознавание не срабатывает.
- **Скорость:** на RTX 3070 YOLOE с трекингом даёт ~44 кадра/с, VLM описывает сцену за ~0,8 с, перевод занимает 0,1–0,3 с. На CPU описание занимает 1,5–3 с.
- **Текстовые запросы YOLOE** кэшируются в `models/yoloe-11s.text_pe.npz`. Текстовый энкодер MobileCLIP (572 МБ) загружается только ради нового слова (~0,7 с) и сразу выгружается.
- **Зависимости:** проверено с `transformers` 4.57. Конфиг токенайзера LFM2.5-VL сохранён в формате 5.x и правится автоматически при загрузке.

## Структура

```
aikoru/
  __main__.py     точка входа, офлайн-окружение
  assistant.py    оркестратор: потоки скана, команд, голоса
  camera.py       фоновый захват кадров
  detector.py     YOLOE (+трекинг ByteTrack), направление и расстояние
  scene.py        состояние треков: что появилось, что ушло
  faces.py        распознавание лиц, база знакомых
  objects.py      память личных предметов (визуальные промпты YOLOE)
  web.py          веб-сервер интерфейса (stdlib): кадры, SSE-события, API
  web/            index.html, style.css, app.js, логотип
  vlm.py          малая VLM (LFM2.5-VL / SmolVLM)
  translator.py   NLLB-200 (CTranslate2)
  voice.py        слово активации, VAD, Vosk
  commands.py     разбор команд ru/kk
  tts.py          Silero TTS с очередью приоритетов
  lexicon.py      словарь объектов, фразы, числительные
scripts/
  download_models.py   загрузка моделей в models/
  selftest.py          самопроверка
```
